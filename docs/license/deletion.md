# 数据移除政策

> 最后核对：2026-07-21。本文说明当前站内申请流程与软删除行为；如页面与保存站内 `/deletion` 的正式政策文本存在差异，以维护者最新公示和实际审核决定为准。

保存站归档公开内容的目的，不意味着内容永远不能移除。与内容相关的本人、权利人或其他受影响方可以提交理由，由具备内容管理权限的管理员审核。

## 一、当前申请入口

现役站内流程适用于文章与剪贴板：

1. 通过 CP OAuth 登录；
2. 打开目标文章或剪贴板；
3. 点击“删除”；
4. 阅读政策并填写理由；
5. 提交后等待管理员审核；
6. 通过或拒绝结果由站内用户通知送达。

当前表单要求理由非空，最长 500 字。旧文档中“至少 15 字”“预计三或七个工作日”“通过率约 50%/80%”等数字没有现役代码依据，已经移除。

## 二、可申请的理由

请提供足以核实的具体事实，例如：

- 内容包含本人或他人的个人信息、账号凭据或其他隐私；
- 内容涉嫌侵犯著作权、名誉权或其他合法权益；
- 内容包含违法、违规、恶意攻击、色情、暴力或明显有害信息；
- 公开赛、团队题目、未公开材料等存在合理保密需求；
- 司法、行政机关或权利人提出合法有效的处理要求；
- 其他确有必要限制公开访问的情况。

“原文已删除”或“内容过时”可以作为背景，但不会自动证明必须移除。请说明你与内容的关系、具体风险、对应段落和可验证证据。不要在申请理由中提交密码、Token、Cookie 或与审核无关的第三方隐私。

## 三、申请校验

系统会在创建申请时检查：

- 申请人已经登录；
- 目标类型是文章或剪贴板；
- 目标 ID 有效且对应归档存在；
- 目标当前未被软删除；
- 理由非空且不超过 500 字；
- 同一用户对同一内容没有仍在等待的重复申请。

同一目标可以存在来自不同用户的申请；同一用户在旧申请已经终结后也可基于新事实重新提交。

## 四、审核状态

申请只有三种状态：

- `pending`：等待审核；
- `approved`：通过，目标被软删除；
- `rejected`：拒绝，目标保持原状态。

通过和拒绝都是终态。管理员可以填写不超过 500 字的处理备注，备注随站内通知发送给申请人。项目不承诺固定处理时限。

## 五、软删除的实际效果

当前自动审核流程执行软删除：

- 普通访客无法继续读取目标正文；
- 页面显示不可查看状态和删除原因；
- 软删除文章同步标记到搜索索引，并从普通搜索中排除；
- 文章不会继续请求相关推荐、历史版本和评论；
- 数据库记录仍保留，供审计与具备权限的管理员查看；
- 管理员可以在确认后恢复内容。

软删除不是物理擦除，也不能保证已经被第三方复制、搜索引擎缓存或下载的内容同步消失。

## 六、硬删除与数据残留

现役站内按钮没有自动硬删除端点。如果请求涉及高风险个人信息、合法权利通知或司法/行政要求，并且软删除不足以降低风险，请通过项目公开的私下联系方式联系维护者，说明需要进一步处置的原因。

即使执行数据库层面的移除，缓存、访问日志、备份和灾难恢复副本仍可能在合理周期内保留，直至轮换或覆盖。项目会在技术与合规条件允许的范围内减少残留，但不能追回已经由第三方保存的副本。

## 七、主动移除与恢复

维护者可以主动软删除违法、侵权、恶意、垃圾或其他明显不适合继续公开的内容。具备内容管理权限的管理员也可以恢复误删内容；恢复后文章重新同步搜索可见状态。

恢复能力不意味着每个通过的申请都会被撤销。审核和恢复都应保留理由，并以保护相关权利和归档完整性为目标。

## 八、滥用

重复提交完全相同、无意义、辱骂性或故意虚假的申请不会提高处理优先级，并可能触发站点的反滥用措施。请不要通过公开曝光敏感材料来“证明”申请，必要证据应使用维护者认可的私下渠道提供。

## 九、其他渠道

无法登录、目标已经软删除、需要硬删除，或申请本身包含不宜公开的材料时，可通过 [QQ 群](https://qm.qq.com/q/QVM9YFEb26) 先联系维护者确认安全提交方式。普通 Bug 仍可使用 [GitHub Issues](https://github.com/laikit-dev/luogu-saver/issues)。
