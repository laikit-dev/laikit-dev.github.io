# AIGC 公约

项目允许使用生成式 AI 辅助开发与写作，但提交者始终对最终结果负责。工具输出不是事实来源，也不能代替理解、测试、评审和许可证判断。

## 基本要求

1. **理解改动**：能解释每个行为变化、数据流和错误边界；
2. **核对事实**：文档以代码、规格和可验证历史为准，不以模型记忆为准；
3. **最小化范围**：不混入无关重构、批量改名和样式漂移；
4. **完整验证**：运行与风险相称的构建、测试、lint 和页面检查；
5. **保护数据**：不把生产配置、Token、Cookie、用户内容或删除申请发送给未授权模型；
6. **尊重许可证**：不复制来源不明或许可证不兼容的代码与文本；
7. **接受责任**：提交者本人处理回归、评审意见和后续维护。

## 后端特别要求

生成代码前同样必须先读、写和回读相关 `spec/*.spec.md`。模型给出的实现如果与规格冲突，应先判断预期行为，而不是偷偷让代码或规格迁就输出。

## 文档特别要求

- 不编造发布日期、贡献者、处理时限、通过率或部署状态；
- 不把人工旧日志包装成 Git 已验证记录；
- 不为了“更丰富”加入不存在的功能；
- 技术说明必须能定位到现役代码、规格或官方依赖文档；
- 自动改写后必须通读中文，去掉空泛重复和不自然术语。

## 禁止事项

- 不理解就复制粘贴；
- 用模型生成的测试去证明同一模型生成的错误需求；
- 隐藏失败检查或降低验收标准；
- 在 commit、PR 或生成文件中添加 AI 产品宣传、虚构署名或共同作者；
- 把模型推断当作项目决策。

好的使用方式是加快检索、生成候选实现、补充测试思路和发现遗漏；最终判断仍由开发者基于仓库事实作出。
